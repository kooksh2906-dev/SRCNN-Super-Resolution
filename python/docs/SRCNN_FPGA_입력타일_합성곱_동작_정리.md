# SRCNN FPGA 입력 타일과 합성곱 동작 정리

## 1. 이 문서의 결론

현재 프로젝트는 큰 이미지를 한 번에 FPGA에 넣는 대신, **32×32 크기의 INT16 타일을 순서대로 FPGA에 전달하여 SRCNN 연산을 반복**하는 구조이다.

- PC/Python: 이미지 전처리, Bicubic 확대, Y 채널 추출, INT16 양자화, 32×32 타일 생성
- FPGA 보드의 PL: Conv1 → ReLU → Conv2 → ReLU → Conv3 및 재양자화
- 보드/호스트 소프트웨어: 타일 송수신과 제어
- PC/Python: 반환된 유효 출력 타일을 합쳐 최종 이미지를 만들고 FP32 결과와 수치 비교

따라서 아래에서 설명하는 **9×9 커널 이동과 3개 합성곱 계층의 계산은 FPGA 연산부가 실제로 수행할 내용**이다. 반면 이미지 파일 처리와 Bicubic 확대는 현재 설계상 FPGA 합성곱 코어가 아니라 PC/Python 쪽 작업이다.

---

## 2. 전체 데이터 흐름

예시로 실제 저해상도 이미지가 128×128이고 배율이 ×2일 때의 흐름은 다음과 같다.

```text
LR RGB 이미지 128×128
        │
        ├─ RGB → YCbCr 변환
        ├─ Bicubic ×2 확대
        ▼
Bicubic Y 이미지 256×256
        │
        ├─ 실수 값을 INT16(F=15)로 양자화
        ├─ Halo를 포함한 32×32 타일 생성
        ▼
32×32 INT16 입력 타일 256개
        │
        ├─ UART/통신으로 보드에 전달
        ▼
FPGA SRCNN 연산
Conv1 → ReLU → Conv2 → ReLU → Conv3
        │
        ▼
각 타일의 32×32 출력
        │
        ├─ 중앙 16×16만 유효 출력으로 사용
        ▼
16×16 출력 블록 256개를 결합
        │
        ▼
최종 Y 이미지 256×256
```

컬러 결과가 필요하면 Bicubic으로 확대해 보관한 Cb/Cr 채널에 FPGA가 계산한 Y 채널을 다시 결합하고 RGB로 변환한다. 현재 SRCNN 모델은 Y 채널 하나만 처리한다.

---

## 3. 32×32는 모델의 커널 크기가 아니다

서로 다른 크기를 구분해야 한다.

| 구분 | 크기 | 의미 |
|---|---:|---|
| 전체 처리 이미지 | 256×256 | Bicubic 확대 후 SRCNN으로 보정할 전체 Y 이미지 |
| FPGA 입력 타일 | 32×32 | FPGA에 한 번 전달하는 데이터 블록 |
| Conv1 커널 | 9×9 | 한 출력 위치를 계산할 때 사용하는 Conv1 가중치 영역 |
| Conv2 커널 | 5×5 | Conv2의 주변 참조 영역 |
| Conv3 커널 | 5×5 | Conv3의 주변 참조 영역 |
| 타일의 유효 출력 | 16×16 | Halo의 영향을 제외하고 최종 이미지에 붙이는 중앙 영역 |

즉, FPGA에는 **32×32 타일 전체가 입력**되고, 그 내부에서 9×9 커널이 한 칸씩 이동하며 Conv1을 계산한다.

---

## 4. Conv1의 9×9 커널 이동

32×32 입력의 좌표를 `0~31`이라고 하자.

첫 번째 9×9 영역은 다음과 같다.

```text
x = 0~8
y = 0~8
```

`0~8`에는 0과 8을 모두 포함하므로 총 9개가 있다.

```text
개수 = 마지막 좌표 - 시작 좌표 + 1
     = 8 - 0 + 1
     = 9
```

커널을 오른쪽으로 한 칸 이동한 두 번째 영역은 다음과 같다.

```text
x = 1~9
y = 0~8
```

따라서 `0~9`는 10개 좌표이므로 9×9 영역이 아니다. 9×9 창은 `0~8`, `1~9`, `2~10`처럼 이동한다.

Conv1 출력 위치 하나를 계산할 때 입력 81개와 가중치 81개를 곱해서 모두 더하고 bias를 더한다.

```text
Conv1 한 출력값 = Σ(입력 9×9 × 가중치 9×9) + bias
```

Conv1에는 필터가 64개 있으므로 같은 `(y, x)` 위치에서 값 하나가 아니라 **채널별로 64개 값**이 생성된다.

```text
Conv1 입력  : 1 × 32 × 32
Conv1 출력  : 64 × 32 × 32
```

여기서 앞 숫자는 채널 수이다.

---

## 5. Padding을 사용하므로 크기가 유지된다

Padding 없이 32×32 입력에 9×9 커널을 적용하면 출력 공간 크기는 다음과 같다.

```text
32 - 9 + 1 = 24
```

즉, Padding이 없다면 Conv1 출력은 24×24가 된다.

하지만 현재 SRCNN은 Conv1에 Padding 4를 적용한다. 입력의 위·아래·왼쪽·오른쪽에 0을 4칸씩 둔다고 생각할 수 있다.

```text
출력 크기 = (입력 크기 + 2×Padding - Kernel 크기) + 1
          = 32 + 2×4 - 9 + 1
          = 32
```

Conv2와 Conv3도 각각 5×5 커널에 Padding 2를 사용하므로 공간 크기가 유지된다.

```text
입력          1 × 32 × 32
Conv1/ReLU1  64 × 32 × 32
Conv2/ReLU2  32 × 32 × 32
Conv3 출력    1 × 32 × 32
```

따라서 32×32 입력이 9×9나 17×17 출력으로 변하는 것이 아니다. Padding을 포함한 현재 모델에서는 최종 출력도 32×32이다.

---

## 6. Radius와 Receptive Field

홀수 크기 커널의 radius는 중심 픽셀에서 좌우 또는 위아래로 몇 칸까지 보는지를 뜻한다.

```text
9×9 커널 radius = (9 - 1) / 2 = 4
5×5 커널 radius = (5 - 1) / 2 = 2
```

SRCNN의 세 합성곱이 연속으로 연결되므로 최종 출력 픽셀 하나의 전체 radius는 다음과 같다.

```text
전체 radius = 4 + 2 + 2 = 8
```

중심에서 왼쪽 8픽셀, 오른쪽 8픽셀을 포함하므로 최종 참조 범위는 17×17이다.

```text
Receptive Field 크기 = 8 + 중심 1 + 8 = 17
```

이를 계층별로 보면 다음과 같다.

| 단계 | 한 출력값이 원래 입력에서 참고하는 범위 |
|---|---:|
| Conv1 출력 | 9×9 |
| Conv2 출력 | 13×13 |
| Conv3 출력 | 17×17 |

계산식은 stride가 모두 1일 때 다음과 같다.

```text
Conv1: 1 + (9 - 1) = 9
Conv2: 9 + (5 - 1) = 13
Conv3: 13 + (5 - 1) = 17
```

중요한 점은 **17×17은 출력 크기가 아니라 최종 출력 픽셀 하나에 영향을 주는 원본 입력의 범위**라는 것이다.

---

## 7. 32×32 입력에서 중앙 16×16만 사용하는 이유

최종 출력 픽셀 하나를 정확히 계산하려면 주변 입력이 radius 8만큼 필요하다. 그래서 최종 이미지에 붙일 16×16 영역 주변에 입력을 8픽셀씩 더 붙인다.

```text
입력 타일 크기 = 왼쪽 Halo 8 + 유효 영역 16 + 오른쪽 Halo 8
               = 32
```

세로 방향도 같으므로 FPGA 입력은 32×32이고, 최종 이미지에는 중앙의 다음 범위만 사용한다.

```text
유효 출력 local x = 8~23  → 16개
유효 출력 local y = 8~23  → 16개
```

이 주변 8픽셀 영역을 **Halo**라고 한다. Halo는 타일 경계 근처의 출력도 이웃 타일 방향에 있는 실제 주변 픽셀을 참고할 수 있게 해 준다.

Halo 없이 256×256 이미지를 단순히 겹치지 않는 32×32 조각 64개로 나누면, 각 조각의 경계에서 주변 정보가 끊겨 타일 경계 자국이 생길 수 있다.

---

## 8. 왜 타일이 64개가 아니라 256개인가

단순 분할만 생각하면 다음 계산이 맞다.

```text
256 / 32 = 8
8 × 8 = 64개
```

하지만 현재 설계에서 32×32는 전부 최종 출력으로 사용하는 블록이 아니다. 중앙 16×16만 사용하므로 타일의 이동 간격, 즉 stride는 16이다.

```text
가로 타일 수 = 256 / 16 = 16
세로 타일 수 = 256 / 16 = 16
전체 타일 수 = 16 × 16 = 256개
```

정리하면 다음과 같다.

```text
FPGA 입력 한 번       : 32×32 = 1,024픽셀
채택하는 유효 출력     : 16×16 = 256픽셀
전체 FPGA 실행 횟수    : 256회
최종 결합 출력         : 16×16 블록 256개 = 256×256
```

## 9. 타일 좌표 생성 예시

출력 블록 위치를 `(tile_y, tile_x)`라고 하면 해당 타일 입력의 전체 이미지 좌표는 다음과 같이 계산한다.

```text
global_x = tile_x × 16 - 8 + local_x
global_y = tile_y × 16 - 8 + local_y
```

여기서 `local_x`, `local_y`는 32×32 타일 내부 좌표 `0~31`이다.

예를 들어 `(tile_y, tile_x) = (0, 0)`인 첫 타일은 전체 이미지의 `-8~-1` 영역까지 필요하다. 이 좌표들은 이미지 밖이므로 0으로 채운다.

두 번째 가로 타일 `(0, 1)`은 첫 타일보다 16픽셀 오른쪽으로 이동한다.

```text
첫 타일의 x 범위   : -8~23
두 번째 타일 x 범위:  8~39
```

두 입력 타일은 겹치지만, 최종 이미지에 붙이는 중앙 16×16 출력 영역은 서로 겹치지 않는다.

---

## 10. 전체 이미지 경계에서의 주의점

전체 이미지 바깥 입력은 0으로 채운다. 또한 Conv1과 Conv2의 bias 때문에 이미지 바깥 위치에 중간 특징값이 생길 수 있으므로, 정확한 전체 이미지 Padding 동작과 일치시키려면 **각 계층의 후처리 단계에서 이미지 바깥 위치를 다시 0으로 마스킹**해야 한다.

즉, 맨 바깥쪽 타일은 단순히 입력만 0으로 채우는 것으로 끝내지 않고 타일 위치 또는 boundary 정보가 컨트롤러에 전달되어야 한다.

이 처리를 적용해야 Python의 전체 이미지 직접 추론과 FPGA 타일 추론 결과가 동일한 기준으로 비교된다.

---

## 11. FPGA 보드에서 실제로 반복되는 동작

타일 하나에 대해 보드가 수행해야 하는 개념적 순서는 다음과 같다.

1. `tile_id`와 INT16 입력 픽셀 1,024개를 수신한다.
2. 입력 타일을 내부 메모리에 저장한다.
3. Conv1의 64개 필터로 `64×32×32` 누산 결과를 계산한다.
4. bias, rounding, shift, saturation 및 ReLU를 적용한다.
5. Conv2의 `32×32×32` 결과를 계산하고 같은 후처리를 적용한다.
6. Conv3로 `1×32×32` 출력을 계산하고 INT16으로 재양자화한다.
7. 중앙 `16×16`, 즉 256개 출력값을 반환한다.
8. 다음 타일에 대해 같은 과정을 반복한다.

FPGA 내부에서는 9×9 영역 하나를 통째로 이미지처럼 따로 만드는 것이 아니라, 메모리 주소와 여러 MAC 연산기를 제어하여 필요한 입력과 가중치를 읽고 곱셈·누산을 반복한다.

## 12. PC/Python과 FPGA의 비교 기준

비교는 이미지를 눈으로만 보는 것이 아니라 각 출력 픽셀의 정수값을 기준으로 한다.

```text
Python INT16 Golden 출력
            ↕ 픽셀 단위 비교
FPGA RTL/보드 INT16 출력
```

주요 검증 항목은 다음과 같다.

- mismatch 개수
- 최대 정수 오차(LSB)
- 평균 오차
- 계층별 Conv/ReLU 출력 일치 여부
- 최종 이미지의 PSNR
- 타일 한 개 및 전체 256개 타일 처리 시간

Python FP32 출력은 원래 모델의 기준이고, Python INT16 Golden은 FPGA가 구현해야 할 고정소수점 계산 규칙의 기준이다. FPGA 결과는 우선 Python INT16 Golden과 일치해야 한다.

## 13. 역할별로 다시 구분

### PC/Python 측

- LR 이미지 파일 읽기
- RGB → YCbCr 변환
- Bicubic ×2 확대
- Y 채널 정규화와 INT16 양자화
- Halo 포함 32×32 타일 생성
- `tile_id + 1,024픽셀` 패킷 생성
- FPGA 출력 수신
- 16×16 유효 출력 결합
- 이미지 저장 및 FP32/Golden/FPGA 결과 비교

### FPGA PL 연산부

- INT16 입력과 가중치 읽기
- Conv1, Conv2, Conv3 곱셈·누산
- bias 정렬
- rounding, shift, saturation
- ReLU
- 계층별 메모리 저장 및 읽기

### 보드 제어 및 소프트웨어 측

- 통신 패킷 수신/응답
- 타일 ID와 경계 정보 관리
- 연산 시작과 완료 제어
- 메모리와 PL 가속기 제어

## 14. 한 문장 요약

**256×256 Bicubic Y 이미지를 출력 기준 16×16 블록으로 나누고, 각 블록에 필요한 주변 8픽셀 Halo를 붙여 32×32 INT16 타일 256개를 만든 뒤, FPGA가 각 타일에 SRCNN 9×9–5×5–5×5 연산을 수행하고 중앙 16×16 결과만 반환하도록 하는 구조이다.**
